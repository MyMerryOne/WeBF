# Implementation Gaps

This file tracks unresolved limitations that affect technical interpretation, operational readiness, or release confidence. Completed package-integrity remediation is recorded below for traceability and is no longer treated as an open gap.

| Status | Area | Gap | Risk | Planned treatment |
| --- | --- | --- | --- | --- |
| In progress | Package integrity | Manifest schema `1.1`, complete member inventory, duplicate/unsafe-path checks, package hash index, and a second RFC 3161 binding for the package index are implemented for new packages. | The external signature adapter, partial-binding status, and historical-package migration boundary remain open. | Complete external signing integration and add explicit manifest/report status for unavailable package binding. |
| In progress | Capture target safety | Capture targets are validated before network metadata collection; HTTP redirects and browser HTTP(S) requests are checked for credentials and non-public addresses, and TLS certificate failures fail closed. | DNS rebinding after validation remains dependent on the operating system resolver and network path; browser egress is not yet isolated at connection time. | Add transport/egress connection enforcement and controlled rebinding validation. |
| Open | Capture status | Stage failures are not yet represented as a structured manifest status. | Partial collection can appear complete. | Add stage status, warnings, and omitted-artifact fields. |
| Completed | Browser diagnostics | Console and page-error listeners are registered before navigation and returned as structured browser results. | Diagnostics are not yet surfaced in the manifest/report status model. | Include diagnostics in the structured capture-status schema. |
| In progress | Browser subresource policy | Browser HTTP(S) subresources are policy-checked, and required isolated egress can now fail closed without `WEBF_BROWSER_PROXY`. | The proxy's connection-time private-peer rejection and DNS-rebinding resistance require controlled deployment validation. | Validate the configured proxy/firewall boundary with live rebinding and private-peer tests. |
| Open | Redirect provenance | The archive currently emphasizes the terminal response. | Redirect context may be incomplete. | Preserve and test redirect chronology. |
| Documented boundary | Terminology | Existing generated packages contain pre-migration labels and schema `1.0`. | Historical output may not match current product language. | Do not rewrite historical packages; regenerate new outputs and document the boundary. |
| Open | Release automation | CI, dependency audit, SBOM, and secret scanning are configured, but release evidence remains environment-dependent. | Release evidence is not operationally proven until retained. | Execute CI and retain the release record, audit result, SBOM, secret scan, and distribution hashes. |
| Open | Italian trust validation | Certificate-chain validation does not validate current AgID Trusted List status, revocation, service identity, or trust-material provenance. | A valid chain could be mistaken for proof of qualified-service status. | Add an explicit trust-validation record and require independent current-list validation. |
| Open | Operator and custody record | The Italian report contains a declaration and signature line but no structured authorization or custody event history. | Identity, scope, storage, and transfer chronology are not independently represented. | Add manifest authorization, environment, and custody-event structures; support external signing. |
| Completed | Malformed artifact verification | Verification now rejects malformed artifact entries without dereferencing them or raising a traceback. | Broader malformed ZIP and package-index cases still need coverage. | Add fail-closed tests for malformed ZIPs, package indexes, and required members. |
| Completed | Documentation and tests | README test guidance now lists the HTTP policy tests, documents explicit timestamp prerequisites, and documents the strict local quality gate. | Timestamp tests still require `pyasn1` and `pyasn1-modules` when the complete suite is run. | Keep dependencies explicit and use the focused test commands for isolated changes. |
| Completed | Czech report wording | The Czech template previously stated that integrity was guaranteed by a qualified timestamp and that admissibility could not be denied. | The report could overstate technical results and legal effect. | Updated the template to use neutral technical-verification language; qualification and legal effect remain separate validation questions. |
